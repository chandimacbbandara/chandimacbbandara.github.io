Intelligent Task Allocation System

An enterprise-grade Learning-to-Rank (LTR) machine learning system and production web application designed to automatically allocate incoming project tasks to the most suitable candidate resources based on technical skill taxonomy, historical performance context, dense semantic neural embeddings, and organizational domain priors.

Assigning incoming project tasks to the optimal resource is critical for maximizing task execution quality, minimizing project delay, and maintaining balanced workload distribution. This system frames resource selection as a Learning-to-Rank (LTR) problem, ranking candidate resources using a score-averaging ensemble of XGBoostRanker and CatBoostRanker (YetiRank objective), augmented with dense text embeddings from SentenceTransformer and domain affinity priors.

  • 0.7676 NDCG@10 achieved by the Ensemble Ranker on held-out test tasks.
  • 0.7283 MRR placing top-fit candidates consistently at rank 1 or 2.
  • Dual-model ensemble combining Optuna-tuned XGBoost (60%) and CatBoost YetiRank (40%).
  • 768-dimensional semantic embeddings via all-mpnet-base-v2 for cosine similarity.
  • Production Gradio web application styled with modern Odoo Enterprise UI and KPI smart buttons.

Executive Overview

In modern software organizations and IT service companies, assigning incoming project tasks to the optimal resource is critical for maximizing task execution quality, minimizing project delay, and maintaining balanced workload distribution. Traditional manual assignment relies heavily on manager intuition, which fails to scale across large candidate pools and complex skill requirements.

The Intelligent Task Allocation System frames resource selection as a Learning-to-Rank (LTR) problem. Instead of predicting isolated binary match probabilities, the system ranks candidate resources for a given query task using a score-averaging ensemble of XGBoostRanker and CatBoostRanker (trained with the YetiRank objective), augmented with dense text embeddings from SentenceTransformer and domain affinity priors.

ℹ️ Key Benchmark Highlights
  • Top-10 Normalized Discounted Cumulative Gain (NDCG@10): 0.7676 achieved by the Ensemble Ranker on unseen test tasks.
  • Mean Reciprocal Rank (MRR): 0.7283 on the test set, placing optimal candidates consistently at rank 1 or 2.
  • Out-of-Vocabulary (OOV) Resilience: Automatic taxonomy expansion and catch-all Skill_Other fallback mechanism prevent out-of-distribution routing failures during live inference.

How It Works

Section 1: Core Allocation Flow

When a project manager submits a task, the system executes a multi-stage evaluation pipeline to transform raw input text and deadlines into a ranked leaderboard of 10 recommended candidates:

  • 1. Task Details Parsing: Captures task name, full description, project context, estimated planned hours, priorities, and deadlines.
  • 2. Skill & Text Understanding: Maps task requirements against a predefined skill taxonomy using exact matching, keyword synonyms, or dense semantic embeddings (all-mpnet-base-v2).
  • 3. Candidate Matching: Pulls profiles from the candidate pool and computes historical project involvement, skill match ratios, and past task volume.
  • 4. Ensemble Scoring: Passes engineered feature matrices through tuned XGBoost and CatBoost ranking models to generate calibrated score distributions.
  • 5. Prior Fusion: Blends model scores with historical department and job position affinity priors to ensure organizational domain alignment.
  • 6. Top 10 Presentation: Sorts candidates, computes fit tiers (Exceptional, High, Strong, Good, Qualified), and renders Odoo-style visual cards and analytical breakdown charts.

Section 3: Backend Execution Pipeline

The backend pipeline executes five distinct operations during inference:

  • 1. Raw Text & Date Formatting: Calculates text length metrics: Task_Name_Length, Task_Description_Length, Task_Text_Length, Task_Word_Count, Has_Task_Description. Computes temporal features: Created_Year, Created_Month, Created_DayOfWeek, Created_Quarter, Days_To_Deadline, Has_Deadline.
  • 2. Logistics One-Hot Encoding: Transforms Estimated_Planned_Hours to logarithmic scale Planned_Hours_Log = log(1 + hours). Applies persisted OneHotEncoder objects for categorical attributes (Task_Priority, Planned_Task_Size).
  • 3. Out-of-Vocabulary (OOV) Skill Mapping: Resolves incoming skill tags against taxonomy columns. Maps synonyms (e.g., Data Analysis to Skill_Data_Science, AI / Deep Learning to Skill_Machine_Learning). If an unrecognized or non-corporate skill is provided, it is automatically assigned to Skill_Other to avoid zero-vector feature corruption.
  • 4. Dense Semantic Embedding Comparison: Encodes task text and candidate historical text profiles into 768-dimensional dense vectors using SentenceTransformer('sentence-transformers/all-mpnet-base-v2'). Calculates semantic_text_similarity using paired cosine similarity:
    $$\text{Similarity}(T, C) = 1 - \text{CosineDistance}(V_{\text{task}}, V_{\text{candidate}})$$
  • 5. Group-Relative Feature Engineering: Calculates standard scores (Z-scores) and mean differences for top candidate features within the current task candidate group to capture relative dominance among competitors.

Section 5: Ensemble Model & Prior Fusion

The final ranking score combines predictions from two Optuna-tuned gradient boosted decision tree rankers and organizational domain priors:

1. MinMax Score Normalization

Raw scores $S_{\text{xgb}}$ and $S_{\text{cat}}$ are scaled per task group:

$$S_{\text{norm}} = \frac{S - \min(S)}{\max(S) - \min(S) + \epsilon}$$

2. Score-Averaging Combination

$$S_{\text{model}} = (0.6 \times S_{\text{norm, xgb}}) + (0.4 \times S_{\text{norm, cat}})$$

3. Prior Fusion

$$\text{Score}_{\text{final}} = (0.4 \times S_{\text{model}}) + (0.6 \times \text{Prior}_{\text{dept}})$$

Feature Engineering & Technical Representation

Feature Engineering Pipeline

The system constructs a 72-dimensional feature matrix for every candidate pair $(T_i, C_j)$:

  • Candidate-Task Skill Matches:
    • employee_task_skill_match_count: Total count of required skills possessed by the candidate.
    • employee_task_skill_match_ratio: $\frac{\text{match\_count}}{\max(\text{task\_skill\_count}, 1)}$.
    • employee_task_skill_strength: Weighted sum of skill proficiency profiles.
    • employee_has_matching_skill: Binary indicator (1 if match count > 0, else 0).
  • Dense Semantic Text Similarity:
    • semantic_text_similarity: Cosine similarity between task description embeddings and historical task text written by the candidate.
  • Historical Experience & Domain Priors:
    • employee_project_task_count: Number of tasks completed by candidate in the specific target project.
    • employee_has_project_experience: Binary flag for project familiarity.
    • Task_Employee_Skill_Match: Interaction metric blending historical candidate skill frequency and department-level skill affinity.
    • dept_skill_prior: Domain prior blending department affinity and job title alignments.

Group-Relative Z-Scores

To enable ranking models to compare candidates within the context of a single task request, group-relative transformation is applied to top features:

$$X_{\text{diff}} = X_{ij} - \bar{X}_i$$
$$X_{\text{zscore}} = \frac{X_{ij} - \bar{X}_i}{\sigma_i + \epsilon}$$

Applied features include employee_task_skill_match_ratio, employee_task_skill_strength, employee_project_task_count, employee_historical_task_count, Task_Employee_Skill_Match, and semantic_text_similarity.
